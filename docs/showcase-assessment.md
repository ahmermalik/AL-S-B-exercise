# Showcase assessment

Assessment date October 29, 2026. This is a design judgment against the supplied exercise and job description, not a prediction of interview results or evidence of delivered software.

## Recommendation

Keep the concept. Agent-prepared close review with a manager decision loop is a strong fit for the role and can demonstrate substantial full-stack engineering ability. Its value depends on accurate findings, reduced operator effort, and visible resolution. The stack and the presence of an agent are not proof of those outcomes.

After reviewing the case choice, the [demonstration case selection assessment](research/demo-case-selection.md) recommends Sunset Ridge as a stronger lead than Campus Edge. It combines original-data duplicate candidates and semantic coding review despite apparently normal summary/status views. Campus Edge remains a useful abstention/revision example. This is a proposal awaiting user agreement.

## Fit with the exercise and role

| Criterion | Why the concept fits | What still needs to be demonstrated |
| --- | --- | --- |
| Business relevance | Recurring accounting preparation, owner-report deadlines, and a named manager user. | The manager can make a useful decision faster with the supplied evidence. |
| It works | The workbook contains concrete duplicate candidates, missing commentary, and completion/evidence discrepancies. | A full import, preparation, review, and revision cycle runs live. |
| Scope judgment | One supplied-data preparation workflow, one review owner, SQLite, and one host. | Avoid expanding into payments, general accounting, or broad budget management. |
| Analytical rigor | Deterministic calculations, source references, explicit unknowns, and distinct review/close statuses. | Correct handling of thresholds, incomplete ledgers, missing approval evidence, and contradictory dates. |
| Ambition and creativity | Agent investigation and evidence-based review can go beyond static drafting. | Show why additional evidence changes the agent's actions or draft. |
| Candor | Missing data and prototype limits can remain visible. | Do not claim the books are closed, duplicate exposure is savings, or a staff role has been eliminated. |
| Adoption and capacity | A manager inbox and practical operator workflow support daily use and handoff. | Measure total effort, including review and follow-up; later validate repeated real use in a pilot. |

The Howard Hughes connection is credible through financial workflows, approval processes, data correctness, and analyst enablement. Describe the user's actual contribution accurately and use original synthetic exercise implementation rather than proprietary Howard Hughes code or data. The exercise demonstrates transfer into third-party property management; it does not establish prior ownership of that company's accounting function.

## Main risks and design responses

1. Manager overload: group common evidence gaps, merge related findings into cases, and give each case a specific decision or question. Evaluate review effort as well as preparation time.
2. Discovery without resolution: make one evidence-return and revision cycle part of the proposed core demo, preserving provenance and remaining uncertainty.
3. Unnecessary agent behavior: use ordinary code for structured checks. Justify the agent through relevant evidence-tool selection, adapting follow-up questions, and revision when new context arrives.
4. Generic AI interface: make source-versioned records, persisted work, controlled transitions, and failure recovery observable in the product.
5. Overselling automation: frame the outcome as automated preparation and focused human review. Missing evidence still requires an evidence owner.
6. Infrastructure consuming the exercise: keep VM deployment repeatable and modest. Discuss it briefly; spend demonstration time on operator decisions and observable engineering behavior.

## Engineering proof

| Behavior | Demonstration |
| --- | --- |
| Data ingestion and provenance | Open the exact original record and source version behind a finding. Invalid records remain visible. |
| Durable orchestration | Refresh or interrupt a run, then recover saved progress without duplicated cases or decisions. |
| Correct domain logic | Show strict policy boundaries and a normalized duplicate candidate independently of LLM output. |
| Controlled agent tools | Show a concise record of relevant evidence retrieval and a missing-evidence stop. |
| Review state and history | Add context, show a revised draft, preserve the earlier version, and require review of changed claims. |
| Graceful degradation | Make the model unavailable in a controlled test; preserve checks, source access, and saved work while marking drafting unavailable. |

This is credible evidence of data handling, backend logic, asynchronous processing, persistence, frontend workflow, and deployment. The small synthetic dataset does not establish production scale or realized business impact.

## Proposed evaluation and measurement

Create a small labelled set of expected findings and non-findings from the workbook. Include invoice normalization, exact policy boundaries, missing approver roles, favorable material variance, unsupported payroll cause, changed evidence, and repeated runs. Use clear denominators when reporting coverage or accuracy; do not manufacture a single overall quality score.

Compare manual and assisted completion of the same selected review tasks. Count preparation, manager review, correction, and follow-up time. Record model latency and cost separately from labor savings. If no representative operator has tested it, label the exercise as a candidate-run evaluation and state that adoption remains untested.

Prepare a short handoff/runbook covering deployment, backup and restore, rule ownership, prompt/model settings, review ownership, known gaps, and how the workflow is supported. This addresses the role's expectation of systems other people can own.
